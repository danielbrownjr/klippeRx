# Diagnostic evidence contract

Approved design direction; exact encoding and implementation validation pending.

## F09 - Evidence contract

### Shared conventions

Versioned typed JSON logical objects, independent of chosen language and database. UTF-8, reject duplicate keys, nonfinite numbers, unrecognized major schema, unknown fields at trust boundary unless explicitly versioned; no coercion of strings to numbers. All bounds measured on encoded UTF-8 bytes as well as item counts. IDs opaque server-issued ASCII tokens <=64 chars; never paths or URLs. Schema version major/minor, allow only explicitly supported minor revisions. Unknown values use null plus reason enum {not_observed, unsupported, stale, incomplete, invalid, redacted, clock_uncertain}; no invented defaults. Unit enum and metric catalog fixed per supported profile. UTC timestamp nullable, boot epoch opaque, monotonic offset in milliseconds nonnegative and meaningful only in same epoch, sequence monotonic per source epoch; never compare monotonic offsets across boots. Freshness derived by receiver using monotonic clock and declared source policy, not trusted sender flag. Keep observed event time separate from ingestion time. Coverage explicitly scoped and lists missing categories. Printer pseudonym installation-local, export-specific pseudonym to prevent unnecessary cross-export linking; no serial/IP/name in export. Runtime installation identity kept server-side, never model input. All evidence content untrusted, even logged macros/comments.

| Object | Required fields and semantics | Proposed hard cap |
| --- | --- | --- |
| Observation | schema, id, printer_alias, source_id, source_kind, epoch, seq, observed_utc, received_utc, monotonic_ms, clock_quality, metric_id, unit, value, unknown_reason, coverage | 2 KiB each; scalar or explicitly catalogued bounded vector <=16 |
| Event | observation envelope plus event_class, mechanism_code, bounded excerpt, excerpt_status, source_revision | 4 KiB; excerpt <=1 KiB sanitized |
| Snapshot | schema, id, alias, capture start/end, epoch, source revisions, consistency, coverage, observation/event handles, missing scopes | 16 KiB metadata; <=128 handles; no inline unbounded file |
| Config evidence | logical source handle, capture revision/digest, disk_or_runtime, coverage, allowlisted section/field type, value or unknown, parser profile | 4 KiB each; <=64 fields per page; no executable macro text |
| Finding | schema, id, rule_id/version, evidence handles, time window, severity, confidence category, observed facts, mechanism, hypotheses, limitations, next observations | 8 KiB; <=16 evidence refs, <=4 hypotheses, <=4 proposed observations |
| Test proposal | id, finding_id, purpose, prerequisite labels, safe observation steps, expected discriminating outcomes, stop conditions, hazard class, required authorization | 4 KiB; <=8 steps; M1 passive observations only |
| Test result | id, proposal_id, observation handles, provenance (synthetic/host/target/human_reported), outcome, measured values, units, uncertainty, limitations | 4 KiB; <=16 refs; never promote reported to measured |
| Export envelope | schema, alias, snapshot/findings, source provenance, freshness/coverage, redaction report, created time, purpose, digest metadata | <=128 KiB total inference input including envelope, fixed instructions/history/context; <=64 records; byte cap wins |
| Provider advice | request id, envelope digest, provider/model label, outcome, bounded advisory text, referenced evidence handles, limitations | <=256 KiB decoded accumulated content; <=1 MiB wire/framing; <=16 KiB per event; displayed text <=32 KiB, explicit incomplete/omitted indicator; no executable markup |

Global ordinary evidence-record bounds: <=32 KiB serialized JSON, nesting <=8, keys <=64, ordinary strings <=512 UTF-8 bytes unless field-specific, string absolute <=4 KiB, arrays <=256 entries. General protocol ceiling depth <=16 and keys <=128; tighter schema wins. Pages <=64 records and <=64 KiB encoded; entire application request <=128 KiB decoded and response <=256 KiB, route-specific smaller caps. Distinguish individual evidence objects from transport envelopes, which have separate total caps. Log context <=64 KiB/source, <=4 sources per extraction, total workspace quota still applies. Moonraker WS <=256 KiB decoded; oversized initial response marks unsupported/partial without hot reconnect. JavaScript-facing integers within exact 53-bit range or opaque decimal strings; reject bool as int. No unbounded joins or pagination. Stable snapshot/revision-bound pagination. Reject oversized transport before full decode; enforce decompressed byte limit and deadline, no unbounded decompression. Validate before persistence; reject malformed required fields, preserve only bounded error classification, no raw payload logging. Never truncate a structured record into invalid JSON; drop whole low-priority records with omission metadata; if required evidence cannot fit, block export. These tighter per-type limits reconcile with the approved F06 global ceilings. Validate exact encoding and per-route limits before implementation acceptance.

### Diagnostic semantics

Severity describes consequence/urgency, not causal certainty. Confidence categories proposed: confirmed_observation, supported_hypothesis, tentative_hypothesis, insufficient_evidence. Confirmed observation means recorded mechanism or measurement, not verified physical root cause. Example synthetic event: Klipper reports heater temperature not rising as expected. Fact: reported shutdown mechanism at captured time; hypotheses: heater power delivery, thermal sensor/coupling, environmental loss or configuration mismatch; none established. Recommend reviewing existing bounded historical temperatures and documented configuration evidence, not energizing heater, opening live hardware or bypassing safeguards. If no corroborating evidence, explicitly say root cause undetermined. Rule output records required and missing evidence and version. No numerical probability without validated calibration. Distinguish configured values, runtime readings, human reports, inferred conclusions and synthetic fixtures. No automatic remediation or control edge. Proposed tests in M1 are passive evidence requests; future physical recipes M4/M5-B require separate review and authority.

### Synthetic example (not a real printer observation)

```json
{"schema":"1.0","id":"obs-fixture-1","printer_alias":"fixture-A","source_id":"moon-status","source_kind":"synthetic","epoch":"boot-fixture","seq":7,"observed_utc":null,"received_utc":null,"monotonic_ms":12000,"clock_quality":"unknown","metric_id":"heater.actual_temperature","unit":"degC","value":null,"unknown_reason":"not_observed","coverage":"partial"}
```

Metric identifiers are proposed catalog names, not verified Moonraker object names. Map exact supported fork fields in a versioned adapter after F05/F06. A missing value cannot be interpreted as zero. Retain raw source mapping internally for provenance, never arbitrary path selection.

### Sanitization and dispatch

Build export from allowlisted structured values, not a regex-only scrub of raw logs. Exclude credentials, auth headers, private paths, filenames, network/serial identifiers, personal names, arbitrary macro/comment text, executable content, and unsupported fields. For allowed short excerpts apply secondary canary/redaction checks; uncertain classification means omit or deny. Redaction report includes categories and counts, not original secret values. Canonical serialization proposed: deterministic UTF-8 JSON with specified key order and number handling; choose exact canonical serialization and cross-runtime verification before implementation, prohibit nonfinite values and ambiguous normalization. SHA-256 over exact immutable bytes to transmit as evidence (digest outside hashed payload); record parameters/account/model/purpose in separate immutable consent binding. Provider adapter may wrap bytes in a fixed API envelope but must not add private evidence. Include all instructions/history/context in total input limit and consent binding. Preview represents exact evidence and declared fixed instructions; immutable provider request parameters also bound. No hidden context. Verify digest immediately before dispatch. No keys in model content. Untrusted provider response rendered escaped plain text; evidence references resolved only against allowed handles; unknown references labeled unsupported. No model-driven retrieval, URL fetching, SQL or commands. Output can never change permissions or dispatch additional requests.

### Retention and collection assumptions

Carry forward gate plan: one selective subscription, thermal <=1 Hz, fallback >=5 s active and >=30 s idle with backoff; detailed ring <=10 min, minute aggregate <=72 h, bounded incidents <=7 days; quotas override age. State <=64 MiB including journal/temp, logs <=8 MiB, normal logs <1 MiB/day, reserve max(128 MiB,10% writable filesystem), one inference inflight, <=1/min and <=30/day configurable lower. CPU/RSS and all detailed allocations in approved F06 above apply. Track both liveness and last observation, support unchanged values, unknown cadence, partial subscriptions and dropped delta counters. Store only app-owned data, no deletion of printer data. Enforce quotas including in-progress writes and reserve; if storage unavailable, pause capture and mark gap, do not fight daemon. Schema migration must be bounded, fail closed on unsupported version, never import authorization from restored evidence. SQLite direction approved; exact target availability and encoding implementation remain unverified.
